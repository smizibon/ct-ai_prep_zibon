# CT-AI Studio — Architecture

## Design principles

1. **Sources are truth, data is derived.** Every piece of content is generated by a script from the
   verified markdown sources (`../markdown/`) into plain-JS data files, then machine-verified by a
   gate script. Hand-written content (cheatsheets) is constrained to compression-only with
   line-cited provenance.
2. **Zero-runtime-dependency.** No frameworks, no CDNs, no fetch. The app is one `index.html` +
   stylesheets + classic `<script>` tags, so it behaves identically over `http://` and `file://`.
3. **Logic is pure and testable.** The exam engine (`js/engine.js`) is DOM-free and unit-tested
   under node; the UI is a thin layer over it.

## Key decisions (why)

- **Data as `<script>` globals, not fetch/JSON.** `fetch()` of local files is blocked on `file://`
  in Chromium; classic script tags are the only channel that works everywhere. ~180 KB total loads
  in well under 100 ms.
- **Verbatim slices over paraphrase.** Study bodies are exact line ranges of the syllabus (the only
  permitted edit rewrites image paths), so fidelity is checked by string equality — not judgment.
- **Stems without options.** The extraction records embed the option list inside the stem; the
  build splits them (SPEC §6A) so the renderer can show options as interactive rows and optional
  shuffle can re-letter without corrupting the verbatim stem.
- **One session slot.** `ctai.session.v1` holds the single active session (sim or practice).
  Starting a new one requires explicit discard; simulations are never pausable (integrity parity
  with the real exam) and survive reloads via an absolute `endsAt` deadline with a clock-drift clamp.
- **Thresholds computed, never hardcoded** — `ceil(0.65 × totalPoints)` reproduces the official
  29/44 and scales for practice sets (33/50, 4/6).
- **Two-register UI.** Calm reading shell (sidebar + 72ch measure) for study; chrome-less cockpit
  (sticky timer bar + palette) for exams. Design tokens are fixed in `styles/tokens.css` with
  WCAG-verified pairs in both themes (docs/plans/design-D3-uiux.md §7).
- **SVG must be created in the SVG namespace.** The DOM factory (`ui.js el()`) routes svg/use/circle/
  line/path… through `createElementNS` and sets `class` via `setAttribute` (SVG `className` is
  read-only). `createElement("svg")` silently yields HTMLUnknownElement — this bug once made every
  ring and icon invisible; the selftest suite now guards it.
- **UI verification is scripted, not manual.** Every interactive element carries a `data-testid`;
  the in-page suite (`#/selftest`) exercises real handlers with real DOM events — no synthetic-input
  flakiness, no browser-automation dependency — and a zero-dependency CDP driver runs it in headless
  Chrome against both http:// and file:// (SPEC Amendment K).
- **Layout values are tokens, not literals.** `--topbar-h`, `--content-pad-top`, `--ch-card-min`
  are the single source for sticky offsets, the study reading-progress negative margin, and the
  chapter-grid column floor; the exam shell zeroes `.content` padding so the cockpit never
  double-pads. The `<svg hidden>` sprite must stay `display:none` (SVG elements ignore the HTML
  `hidden` attribute and otherwise occupy a 300×150 box — the "gap above the header" bug).

## Verification model

| Gate | Command | What it proves |
|---|---|---|
| A — data | `python3 tools/verify_content.py` | 51 verbatim LO slices, LO/question joins equal merged.json, 46Q/50pts, cheatsheet src+digit traceability + word caps, glossary integrity (118/31), questions.js structural invariants, intel counts |
| B — logic | `node tools/tests/engine.test.mjs` | scoring for all 5 question types, all-or-nothing multis, thresholds, timer math + drift clamp, shuffle determinism, attempt archival |
| B — renderer | `node js/md.js --selftest` | markdown subset golden cases |
| C — UI | `node tools/tests/ui.test.mjs [base]` | 24 in-page scenarios (js/selftest.js, `#/selftest` route) driven through headless Chrome over raw CDP: reveals, widgets, sim flow + PASS math, review filters, resume, leave-guard, mobile sheet, plus layout assertions (topbar flush, content padding tokens, exam-shell seam-free) and a testid walk that fails if any interactive element lacks a `data-testid`. Runs against `http://127.0.0.1:8765` and, with `file://$(pwd)` as base, the file:// deployment constraint. Anchors on the site-wide `data-testid` contract (see AGENTS.md) |
| C — layout audit | `node tools/probe_layout.mjs` | per-route geometry (topbar offset, content paddings, page height vs viewport) + missing-testid report + JPEG screenshots to `tools/shots/` — numbers first, images on demand |
| C — visual | screenshot pass (headless capture, vision-checked) | dashboard light/dark, learning reveal, A4 connectors, sim results ring/PASS/grid |

Regeneration is idempotent: `tools/cheatsheets/*.json` are merged into the chapter files at emit
time (never hand-edit `data/chapter-*.js`).
